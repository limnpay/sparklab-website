# Stack Audit — SparkLab Website

This is a custom React single‑page app with an Express + tRPC + MySQL backend, built on a "Manus WebDev" template. There is no CMS or page builder — every page is hand‑coded in `client/src/pages/*.tsx`. Content is hardcoded inside the components.

## In plain terms

- A **React 19** front end (the marketing site) is built with **Vite 7** and **Tailwind CSS v4** and routed client‑side with **Wouter**. All pages live in `client/src/pages` and are hand‑coded; there is no headless CMS or visual page builder.
- An **Express 4** API server (in `server/`) runs alongside it. It serves the React app (via Vite middleware in dev, static files in prod), exposes a **tRPC** API at `/api/trpc`, and handles **OAuth callbacks** at `/api/oauth/callback`. Only two pieces of real backend logic are wired up: a contact form and a newsletter signup. Both write to a **MySQL** database via **Drizzle ORM** and notify the project owner through an external "Manus Forge" notification service.
- The single Node process runs everything (it picks the first free port starting at `3000`). Build outputs go to `dist/public` (client) and `dist/index.js` (server).
- The codebase carries a lot of unused template scaffolding inherited from the Manus WebDev starter: an OAuth/auth flow, an `AIChatBox` component, server `llm.ts`, `imageGeneration.ts`, `voiceTranscription.ts`, `map.ts` proxy helpers, `storage.ts` (S3 + Forge storage proxy), a `ComponentShowcase` page, a `DashboardLayout`, etc. None of these are reached by any route in `App.tsx`.

### Back end (`server/`)
| Concern | Choice |
| --- | --- |
| Runtime | Node.js (ESM); dev uses `tsx watch`, prod uses `esbuild`-bundled `dist/index.js` |
| HTTP | Express 4 |
| API | tRPC 11 via `@trpc/server/adapters/express`, mounted at `/api/trpc` |
| ORM | Drizzle ORM 0.44 on `mysql2` |

### Build / tooling
- `vite` (`vite.config.ts`) is the dev server in development and the production bundler.
- The Vite config wires in three Manus‑specific plugins: `@builder.io/vite-plugin-jsx-loc`, `vite-plugin-manus-runtime`, and the standard `@tailwindcss/vite`.
- `esbuild` bundles the server entry to `dist/index.js`.
- Type checking: `tsc --noEmit` (`pnpm check`).
- Tests: `vitest` (two suites: `server/forms.test.ts`, `server/auth.logout.test.ts`).
- Formatting: `prettier`.
- Package manager: `pnpm@10.4.1` (declared); a custom patch on `wouter@3.7.1` ships via `pnpm.patchedDependencies`.

### CMS / page builder
**None.** Pages are React components with content inlined. The few `*.md` files at the repo root (`site-structure.md`, `IMAGE_AUDIT.md`, the various `*photo*.md` files, `ideas.md`, `todo.md`) are working notes, not consumed by the app.

## How it is meant to run locally

1. **Prerequisites:** Node 20+ (the `package.json` `pnpm` field is `>=10`; lockfile was generated by pnpm 10.4.1) and pnpm. A MySQL database is required for the contact and newsletter forms to actually persist; without it both endpoints throw "Database not available". The rest of the marketing pages render without a DB.
2. **Install:** `pnpm install`
3. **Environment:** copy a `.env` into the repo root containing at minimum:
    - `DATABASE_URL` — MySQL connection string (e.g. `mysql://user:pass@host:3306/sparklab`)
    - `JWT_SECRET` — used to sign session cookies (`server/_core/sdk.ts`)
    - `VITE_APP_ID`, `OAUTH_SERVER_URL`, `OWNER_OPEN_ID` — Manus OAuth identifiers
    - `BUILT_IN_FORGE_API_URL`, `BUILT_IN_FORGE_API_KEY` — Manus Forge endpoint and key, used by the owner‑notification helper and the storage proxy
    - `VITE_OAUTH_PORTAL_URL` — base URL of the Manus OAuth portal (used by `getLoginUrl()` on the client)
    - `VITE_ANALYTICS_ENDPOINT`, `VITE_ANALYTICS_WEBSITE_ID` — Umami analytics; the `<script>` tag in `client/index.html` only works if these are interpolated by the host
    - `VITE_FRONTEND_FORGE_API_KEY`, `VITE_FRONTEND_FORGE_API_URL` — Google Maps proxy (only needed if `Map.tsx` is ever rendered; it currently is not)
    - `PORT` — optional, defaults to `3000` and falls forward to the next free port if busy
4. **Migrate database (optional):** `pnpm db:push` runs `drizzle-kit generate && drizzle-kit migrate`.
5. **Start dev server:** `pnpm dev` (runs `tsx watch server/_core/index.ts`). It boots Express on port 3000+, mounts Vite as middleware for the React app, and watches both server and client for HMR.
6. **Open** `http://localhost:3000/`.

## How it is meant to deploy

The repository expects a single‑process Node deployment:

1. `pnpm install --prod=false`
2. `pnpm build` — `vite build` writes the static client into `dist/public`, then `esbuild` bundles the server to `dist/index.js`.
3. `pnpm start` — `NODE_ENV=production node dist/index.js` boots Express, which serves `dist/public` as static files and falls back to `index.html` for client‑side routes.
4. Run the same env vars as in development. Provide a managed MySQL instance and run `pnpm db:push` once against it.

There is no `Dockerfile`, no `Procfile`, no `vercel.json`, no `netlify.toml`, no CI config. The plugin names (`vite-plugin-manus-runtime`, the `__manus__` debug collector in `public/`, the Manus OAuth/storage SDKs) suggest the project was originally hosted on the **Manus** platform, which would supply most of the env values automatically.

## Notable smells discovered during the stack audit

- **Dead template code** ships in the bundle: `AIChatBox`, `ManusDialog`, `Map`, `DashboardLayout`, `DashboardLayoutSkeleton`, `ComponentShowcase`, the `_core/hooks` package on the client, and the whole `server/_core/{llm,imageGeneration,voiceTranscription,map,dataApi}.ts` set. The marketing routes never import any of it.
- **Image hosting is brittle.** Every page hero/gallery on the site references hot‑linked URLs at `https://files.manuscdn.com/user_upload_by_module/session_file/310519663096503204/...`. The `client/public/images/` folder only holds the logo and favicon. If Manus expires those upload URLs the site goes mostly blank.
- **OAuth is wired up but no UI uses it.** `getLoginUrl()` is referenced by `main.tsx` to redirect on 401s, but the marketing site never triggers auth.
- **`patches/wouter@3.7.1.patch`** targets a version that isn't installed (the lockfile pins `wouter@3.3.5`); pnpm will warn but proceed.
- **Two SQL migration files** in `drizzle/` are not registered in `drizzle/migrations/` — the migrations folder is empty.
- **The `<script>` tag for Umami analytics** uses literal `%VITE_ANALYTICS_ENDPOINT%` / `%VITE_ANALYTICS_WEBSITE_ID%` placeholders. Vite does not interpolate them by default (it would need `define`/`html.transform`), so analytics is effectively off unless a host pre‑processes `index.html`.
